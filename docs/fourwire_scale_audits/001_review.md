1. **High — Smoke provenance is incorrect.** `smoke()` reads HEAD **after** training, so job 13586491 reports `a0b5e19` despite starting at `b377e92`. Those commits have identical training source; the commit discrepancy therefore does **not** explain the loss difference. Minimal fix: capture commit and cleanliness before training, verify them afterward, and reject drift. Use an immutable checkout and unique output paths; both runs currently share checkpoint/report destinations. Evidence: [fourwire_scale_train.py:294](src/gencodoe/fourwire_scale_train.py:294).

2. **High — “Fully zero-shot: no target label used” contradicts the physical-prior design.** Every network’s U1 uses its Thevenin equivalent fitted from the first **500 target training candidates**. This is target-label information even when model weights receive no target training. At B=200, physical identification also uses candidates beyond the model’s fitting budget. The protocol explicitly defines B narrowly, so disclose this additional dependence rather than claiming label-free deployment. Evidence: [protocol:132](docs/fourwire_scale_protocol.md:132), [protocol:276](docs/fourwire_scale_protocol.md:276), [fourwire_scale.py:206](src/gencodoe/fourwire_scale.py:206).

3. **Medium — The Numba informational timer includes reference checking.** The timer stops only after `compare_to_reference()` has computed voltage/current errors and convergence comparisons. The PyTorch timer stops **before** that work. Consequently, the reported Numba slope cannot be described as marginal sweep solve cost. This affects B4, although these measurements are explicitly outside E2. Evidence: [fourwire_scale.py:388](src/gencodoe/fourwire_scale.py:388).

4. **Medium — Isolation and provenance checks have gaps, although I found no actual training leakage.**
   - With the committed manifest, `load("test")` fails before constructing a path, and returned arrays are hash-checked. `pretrain()` loads only train/val; its scalers use training data. Validation selects checkpoints and stopping, as prescribed.
   - The constructor accepts replacement **manifest and label-commit arguments**; manifest filenames are unconstrained, and paths are not checked for traversal or symlink resolution. Thus “no path or override” overstates the protection. A redirected path can read test bytes before failing its hash check.
   - The integrity checker discards actual shard provenance and trusts unit-manifest provenance; `all_ok` does not enforce one common commit across units.
   
   My independent check found all **936 actual shard provenances clean and at 6ad2af6**, so these are enforcement gaps, not demonstrated contamination. Evidence: [fourwire_scale_data.py:28](src/gencodoe/fourwire_scale_data.py:28), [fourwire_scale.py:569](src/gencodoe/fourwire_scale.py:569), [tests:106](tests/test_fourwire_scale_train.py:106).

5. **Medium — Validation loss has an inherited aggregation defect, and smoke scheduling needs disclosure.** Each batch loss is normalized by near-limit **weight sum**, then evaluation averages those losses using **converged-state counts**. This is neither the global weighted loss nor the ordinary mean state loss; batch composition affects checkpoint selection. ENWL1 has the same defect. Both trainers also set cosine `T_max=epochs`: this smoke uses learning rates **0.001, 0.00075, 0.00025**, whereas a 60-epoch fit starts **0.001, 0.000999315, 0.000997261**. The smoke is therefore not the first three epochs of final training. Evidence: [scale trainer:173](src/gencodoe/fourwire_scale_train.py:173), [ENWL1 trainer:187](src/gencodoe/fourwire_train.py:187), [scale trainer:147](src/gencodoe/fourwire_scale_train.py:147).

6. **Low — “Loss unchanged” is not numerically exact.** The new VPN scale uses population SD through NumPy/Moments; ENWL1 uses Torch’s sample SD, with different arithmetic precision. On identical network_25 training inputs I obtained **1.481734585e−4 versus 1.481742802e−4**. Other differences are documented pooling, first-2,000-converged-state sampling **per network** for VPN/KVL scales, and replacing indeterminate targets with finite placeholders. Architecture, optimizer and loss coefficients match. No val/calib/test values enter the displayed scaler calculations. Existing scaler tests do not establish loss equivalence. Evidence: [scale trainer:100](src/gencodoe/fourwire_scale_train.py:100), [ENWL1 trainer:143](src/gencodoe/fourwire_train.py:143), [tests:140](tests/test_fourwire_scale_train.py:140).

However, an empirical linear timing fit is not a guaranteed runtime bound: training-fit R² is only **0.8481/0.8466**. Preparation, initial validation, checkpoint writes, calibration and test work are outside the formula. Evidence: [fourwire_scale_train.py:261](src/gencodoe/fourwire_scale_train.py:261).

**B4 — Descriptive arithmetic supported; solve-cost and causal interpretation overstated.** On the **18 matched networks**, model/Numba ratios span **1.068–4.051**, median **1.640**, aggregate **1.442**. Network_8 has ratio **1.102** at **610 buses**; network_15 has **1.534** at **1,096 buses**; network_17 has **1.068** at **1,668 buses**. Size alone does not explain the ordering.

The matched-network slopes are **0.3629 µs/bus** for model validation and **0.3412** for the Numba field; excluding nonconverging networks gives **0.2590** for Numba. But finding 3 prevents calling that sweep-only cost. Further biases run both ways: precomputed features/U1 favor the model; validation loss penalizes it; full voltage/current materialization and reference checking penalize Numba. Batch sizes and CPU allocations differ. The raw GPU-sweep field is faster than Numba on **7/18** matched networks. These are not comparable E2 deliverables, and “mostly fixed overhead” is not causally established.

**B5 — Supported as a possibility, not an achieved result.** The protocol includes OpenDSS rescue in sweep end-to-end time. A successful screen could avoid expensive rescues and win overall despite higher prediction cost. GENCO’s deferred nonconverging states incur that rescue too. Evidence: [protocol:118](docs/fourwire_scale_protocol.md:118), [protocol:181](docs/fourwire_scale_protocol.md:181).

C — Paper framing:

- Presently supported: implemented four-wire GENCO-style training, smoke feasibility, and exact-solver conversion agreement on **24/25 networks**.
- Presently unsupported: better final model accuracy, E2 speed superiority, E3 transfer success, or label-free deployment.
- E2 claims require the frozen six networks, complete pipelines, ≥1.10 speed-up, interval excluding 1, and both safety counts zero.
- E3 claims require the frozen B=1,000 comparison over **23 fresh networks**, seeds and safety conditions; disclose identification, validation and calibration labels.
- Report false-unsafe decisions, fallbacks, indeterminate states, envelope checks, rating sensitivities and negative outcomes.
- Preserve amendments and both smokes; resolve chronology/provenance. Do not change endpoints, networks, stresses, baselines or thresholds to obtain superiority, reuse test results for tuning, or retrospectively call exploratory changes preregistered.
