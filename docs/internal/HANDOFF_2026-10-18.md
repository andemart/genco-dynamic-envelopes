## 4. Hydra (VUB) operating notes

- SSH alias `hydra`. Project dir `/data/brussel/107/vsc10719/genco-dynamic-envelopes`.
- Partitions: `zen4` (CPU) and `ampere_gpu` (A100). Module `Python/3.12.3-GCCcore-13.3.0`, venv `.venv`.
- **Hydra is a git checkout.** Every Slurm script verifies `GENCODOE_COMMIT == git rev-parse HEAD` and a clean tracked tree. To deploy commit `C`:

  ```
  rsync -a .git/ hydra:$D/.git/
  ssh hydra "cd $D && git reset -q --hard C && git status --porcelain --untracked-files=no | wc -l"   # must print 0
  ```

  Use `reset --hard`, not `checkout`. Copying `.git` also copies the local index, so `checkout` silently does nothing. `reset --hard` leaves untracked data alone.
- **Lessons learned the hard way:**
  1. **OpenDSS poisoning.** A fresh OpenDSS engine whose first solve diverges never recovered, so every label was 0. Fixed: `UnbalancedENWL1` primes itself with a no-load solve and raises `OpenDSSEngineError` on any failed reset.
  2. **Stale file caches.** Compute nodes served stale contents for files re-created under **reused names**. Always write corrected data to fresh paths, and hash-verify on a compute node before use.
  3. **Memory.** `load_truth` on `datakit_v2` needs more than 8 GB; use 48 GB.
  4. Write outputs atomically (`.partial` then `os.replace`). Check tests with the real exit status, not through `| tail`.
- Use `GENCODOE_VOLTAGE_LIMITS=uk_esqcr` (UK 216.2–253 V on base 240.18 V → 0.9002–1.0534 pu).

## 6. Four-wire GENCO extension: finished (branch `ander-unbalanced-genco`)

**Protocol.** `docs/unbalanced_genco_protocol.md`, with amendment 1 (frozen configuration; the binned screen was replaced by global conformal margins after a disclosed validation dry run) and amendment 2 (post-result disclosures and corrected attribution).

**Run record.** `results/run_manifest_fourwire.json` holds the commits, job IDs and SHA-256 of every label shard, the Thevenin file, embeddings, checkpoints and evaluation. Label integrity for all four splits (test checked after evaluation) is in `results/fourwire_label_integrity_*.json`.

**Code.** `fourwire_net.py`, `fourwire_labels.py`, `fourwire_model.py`, `fourwire_train.py`, `fourwire_eval.py`, `fourwire_prior_check.py`; tests in `tests/test_fourwire.py`.

**Result** (`results/fourwire_eval_test.json`, committed unchanged in c20b96b):

| Method | V_pn MAE (pu) | OpenDSS fallback | False-safe | End-to-end per state |
|---|---|---|---|---|
| U1 (one-step four-wire sweep) | 3.20e-3 | 35.8% | 0 | 10.9 ms |
| **PhaseGraph** (GENCO-style GNN residual) | **2.91e-4** | **5.8%** | 0 | 2.1 ms |
| PhaseGENCO (+ frozen balanced-GENCO embeddings) | 4.41e-4 | 11.8% | 0 | 4.6 ms |
| Iterated four-wire sweep U3 | 3.6e-6 | 0.1% | 0 | 5.5 ms (unoptimised CPU) |
| Balanced GENCO / balanced sweep | — | 63.0% | 0 | about 19.5 ms |

- **Primary criterion (PhaseGraph vs U1): met.**
- **GENCO-specific criterion 9b: not met.** PhaseGENCO is worse by +6.0 points, CI [+5.3, +6.7].
- **Permitted summary:** "A GENCO-style phase-aware GNN can correct a cheap four-wire prior, but pretrained balanced-GENCO representations add no value here, and a specialised classical four-wire sweep remains the accuracy leader."
- **Not a causal claim.** U1 is already phase-aware, so the result does not show that phase-aware representation itself caused the improvement.
- **Side finding** (not a GENCO result): the vectorised iterated four-wire sweep matches OpenDSS to about 1e-6 pu and could replace most OpenDSS fallbacks.
